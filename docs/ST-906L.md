# SinoTrack ST-906L

Research done 2 Oct 2026 from vendor material, Traccar's own protocol
documentation and an H02 integration reference. **The protocol, port and SMS
configuration are confirmed from documentation. The device itself is still
untested**, and the hardware questions below remain open.

**Revised 13 Oct 2026** after a second pass that went back to the ST-906
manual's own settings pages. Two claims did not survive it and are withdrawn in
place, with the reasoning left visible rather than quietly deleted:

- the "comma form" command set (`apn,...#`, `server,0,...#`, `mode,1#`) is not in
  this model's manual and has been removed — see *SMS configuration*;
- "the tracker is unverified" stands, but the earlier text implied the commands
  were equally confirmed, and they were not.

The same pass corrected the `803`/`804`/... verb-plus-password split, which an
earlier draft had as four digits of verb and would have produced commands the unit
definitely ignores. `scripts/connect-tracker.py` now generates this sequence
directly, and a test asserts the generator and
[`TRACKER-SETUP.md`](TRACKER-SETUP.md) still agree.

## Protocol: H02 over TCP 5013

Confirmed from three independent sources:

- Traccar's protocol list includes `h02`
- Traccar's *"Identify a GPS Tracker Protocol"* page states: *"If your device is
  using the H02 protocol (correct port **5013**), decoded message text would start
  with `*HQ`, and end with a number sign `#`"*
- An H02 integration reference lists Sinotrack, Cantrack and Secumore as the H02
  family, on port 5013

So **the specification's H02/5013 pairing is correct.** (Navixy lists 47735 for
`cantrack`, but that is Navixy's own listener, not Traccar's.)

### What H02 carries

GPS, speed, altitude, heading, street address, GPS accuracy, **ignition status**,
odometer, engine hours and battery level. Ignition is available, which is what we
need for idle-versus-driving.

### Confirming on the box

```bash
tcpdump -i any -n 'tcp port 5013' -w /tmp/h02.pcap
```

In Wireshark, follow the TCP stream from the tracker. The first payload is the
login packet and carries the identifier. Position rows look like:

```text
*HQ,4210209006,V1,201844,A,2608.9437,N,08016.2521,W,000.80,000,150317,FFFFF9FF,310,260,0,0,6#
```

- `4210209006` - IMEI
- `A` - fix **valid**; `V` means **invalid** (weak/no antenna). If you only ever
  see `V`, suspect the antenna before the tracker.
- the `*HQ,` prefix and trailing `#` are how you confirm you are looking at H02
  and not some other protocol.

## SMS configuration

Taken from the ST-906 manual's own settings pages. This device is configured
entirely over SMS and ignores anything it does not recognise **silently**, so the
list below is the manual's set and nothing else.

### The commands

| SMS | Purpose |
|---|---|
| `8030000 <apn>` | set the APN. Add `<user> <password>` only if the carrier demands them |
| `8040000 <ip> <port>` | point at a server - e.g. `8040000 203.0.113.10 5013` |
| `8050000 <seconds>` | reporting interval with ignition on (manual default 20) |
| `8090000 <seconds>` | reporting interval with ignition off (manual default 300) |
| `7100000` | select GPRS mode explicitly |
| `7000000` | select SMS-only mode. **Do not send this** - it stops the reporting |
| `RCONF` | read the configuration back |

**Reading the code.** `803` / `804` / `805` / `809` / `710` is a three-digit verb
and `0000` is the unit's four-digit password. If the password has been changed,
replace those four digits and keep the three-digit prefix. This distinction
matters: `8030` followed by the password is eight characters, the unit ignores it,
and with no screen and no reply the symptom is identical to a dead SIM.

**For our stack, the server command becomes:**

```text
8040000 <your-public-ip> 5013
```

### The two replies that matter

- **`SET OK`** is the documented reply to a setting command that worked.
- **`RCONF`** replies with the current configuration: the mode, the APN, the
  server IP and port, and the upload intervals.

Send `RCONF` and read it. Without a read-back the only evidence that provisioning
worked is a packet arriving on the server, and that one symptom has at least six
causes — a wrong APN, a wrong server address, a wrong port, a firewall, a bad SIM,
and a command the unit ignored are all indistinguishable from the dashboard.

### Order of operations

Set the **APN before anything else.** The device has no screen to report an APN
failure, so a wrong APN looks exactly like dead hardware. Test the SIM in a phone
first.

### The UDP/TCP claim, withdrawn

> An earlier revision of this document told you to send **`mode,1#`** as a
> mandatory step, on the grounds that some H02 firmware mixes UDP and TCP on one
> connection so that UDP keep-alives arrive as garbage on Traccar's TCP-only
> listener.
>
> **That was not verifiable and has been removed.** `mode,1#` is not in the
> ST-906L manual; the claim comes from a single third-party page. The mechanism as
> described is also not how the transports work — UDP datagrams are not carried
> *inside* a TCP connection. Traccar's own forum shows H02 received over both TCP
> and UDP, which is a normal configuration choice, not a firmware bug.
>
> If you do see a connection that opens and then produces garbage, resending
> `mode,1#` is a cheap thing to try. It is not a required step and it is not a
> known fix.

### Reporting intervals

`8050000` is the one that matters for driving hours. `8090000` is what the unit
does parked, which on a 24/7 install is most of the night.

The manual gives a **10-second floor**, and values below it — `T=0` in particular —
stop GPRS reporting altogether. On the server that reads as a dead tracker, so
do not go below 10.

### Do not commit these to Git

They are firmware-specific and a wrong one can leave the device deaf. They are
documented here so the sequence is recoverable; the per-unit password is not.

## Two capabilities you should refuse

### 1. Voice monitoring (MIC)

The ST-906L has a microphone and the vendor advertises voice monitoring.

**Do not enable this.** Recording conversations inside an Italian work vehicle is
worker monitoring under Art. 4 L.300/1970 and requires a formal authorisation
process, works-council involvement depending on the arrangement, and carries real
GDPR exposure. It is also the fastest way to end the client relationship badly.

Leave the audio capability unconfigured. If a client ever asks for it, that is a
conversation about consent, signage and legal sign-off - not a settings change.

### 2. Remote engine cut-off relay

Some ST-906L variants ship with a relay for remote immobilisation.

**Do not wire a fuel-cut relay into a working truck.** Cutting fuel on a moving
HGV is dangerous, and an accidental command becomes a safety incident. Only fit it
if there is a written, specific requirement, and never as part of a default
install.

Prefer the variant **without** the relay if one is available.

## Backup battery

No internal battery is documented for the ST-906L - unlike the ST-905L (5000 mAh)
and ST-915L (10000 mAh) in the same range, which are battery-powered devices.

Treat it as **no backup battery** until the vendor confirms otherwise. That has a
direct design consequence:

> With power taken only from ACC, the tracker is silent whenever the vehicle is
> parked and the ignition is off - which is most of the night.

That is acceptable if you only care about driving hours. It is **not** acceptable
if you need to locate a parked, powered-down truck, or want the tracker to buffer
and replay positions after it regains power.

**So: wire the tracker to a constant fused positive, not to ACC alone.** Use the
ACC input only as the ignition *signal*, never as the tracker's power source.

Confirm with the vendor, and test it (bench test A10).

## LTE bands - the question to ask before buying

**Not documented anywhere we could find.** This is the single most important
unverified item for an Italian fleet.

European rural coverage depends heavily on **B20 (800 MHz)** and **B28 (700 MHz)**.
Low-cost trackers built for the Chinese market very often ship with a modem that
has **B1/B3/B7/B8 only** - excellent in a city, and increasingly marginal in the
countryside, which is where trucks spend much of their time.

Ask the vendor explicitly:

> Which LTE bands does the ST-906L support? Is B20 (800 MHz) and B28 (700 MHz)
> present? Is the unit the EU/global variant?

If the answer is no B20 and no B28, weigh the tracker against a device with an
explicit European modem - the coverage gap is invisible until a truck is in the
wrong place.

## Two variants exist

| Variant | Notes |
|---|---|
| `ST-906L` | 2G+4G, SOS button, relay to cut engine off, MIC |
| `ST-906L 4PIN` | 2G+4G, 4-pin connection, relay optional |

Confirm with the seller **which** one you are getting, and whether the relay is
fitted. The 4-pin harness is what you want for a truck install.

## Remaining unknowns

1. **LTE bands** - ask first, before ordering
2. **Backup battery** - expect none, confirm
3. **ACC pinout** on the 4-wire harness - ask for the diagram
4. **Reporting interval range**, and whether it is configurable remotely
5. **Offline buffering** - does it store positions and replay on reconnect?
6. **IMEI registration** - the vendor warns units must be IMEI-registered
   locally. Confirm the process for Italy/EU.
7. **CE/RED certification** for the EU - vendor claims CE/RoHS; ask for the
   declaration.

## SIM

Choose deliberately - this is a recurring cost and the easiest thing to get wrong:

- **Data-only M2M/IoT SIM**, not a consumer SIM.
- Confirm coverage for **every** country where the trucks operate. Italian
  consumer SIMs roaming in France can cost a large amount per MB, and a tracker
  that silently stops reporting because of roaming charges looks exactly like a
  hardware fault.
- Prefer a provider that publishes roaming coverage and the bands used.
- Disable SMS and voice add-ons the tracker does not need.
- Set up spend alerts. Position reporting is small, but a misconfigured APN can
  generate large bills quickly.
