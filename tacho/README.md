# Tachograph service

Tachograph `.DDD` import, activity normalisation and driving-time reporting for
GPS_Tracer.

Full documentation: [`../docs/TACHO-SERVICE.md`](../docs/TACHO-SERVICE.md). The
caveats that matter most are repeated here because they are easy to miss:

- **Calculations are not legal findings.** No figure from this service has been
  validated against a trusted tachograph analysis report. See
  [`../docs/DRIVING-TIME.md`](../docs/DRIVING-TIME.md).
- **The parser has only been tested against synthetic fixtures** generated by this
  repository. It has never been run against a real driver card.
- **Vehicle-unit downloads are detected and refused**, not parsed. GEN2/GEN2v2 too.

---

## Layout

```
tacho/
├── tacho/
│   ├── parsers/          gen1.py (clean-room decoder), external.py (adapter),
│   │                     base.py (contract + registry), errors.py
│   ├── fixtures/         gen1_writer.py — synthetic .DDD encoder for tests
│   ├── domain/           activities.py — activity model, spans, per-day totals
│   ├── rules/            driving_time.py — versioned EU rules engine
│   ├── api/              app.py (FastAPI), security.py (token + roles)
│   ├── db.py             connection + checksum-verified migration runner
│   ├── storage.py        content-addressed private object store
│   ├── importer.py       ingest pipeline, dedupe, persistence, audit
│   ├── repository.py     read queries (coverage, timelines, reports)
│   ├── worker.py         queue consumer (or --once)
│   └── config.py         environment configuration, validated at startup
├── migrations/           ordered, immutable .sql files
├── tests/                327 tests; the DB-backed ones need PostgreSQL
├── Dockerfile            one image, two entrypoints
└── requirements*.txt     pinned
```

The parser, the activity model and the rules engine import **nothing outside the
standard library**. Only the HTTP and database layers have dependencies. That is
deliberate: the code that decides whether somebody's driving hours are right should
not change because a library was upgraded.

## Run it

```bash
# Via the stack (recommended)
cd .. && docker compose up -d tacho-api tacho-worker

# Health
curl -s http://127.0.0.1:8084/healthz

# Drain the queue once and exit
docker compose run --rm tacho-worker python -m tacho.worker --once
```

Requires `TACHO_API_TOKEN` — the service refuses to start without one, because it
serves driver personal data. Generate with `openssl rand -base64 32`.

## Test it

327 tests: 224 parser, 46 driving-time, 22 external adapter, 35 database-backed.

```bash
python -m pytest tests/ -q                      # logic only, no database

# Database-backed: use a THROWAWAY PostgreSQL. The suite truncates tacho_* tables.
docker run -d --rm --name tacho-test-db -p 127.0.0.1:55432:5432 \
    -e POSTGRES_PASSWORD=test -e POSTGRES_USER=test -e POSTGRES_DB=test postgres:16-alpine
TACHO_TEST_DATABASE_URL=postgresql://test:test@127.0.0.1:55432/test \
    python -m pytest tests/ -q
```

Setting `TACHO_TEST_DATABASE_URL` is treated as a promise that a database is
reachable. If it is set and the database is missing, the run **fails** rather
than skipping, so a dead database can never masquerade as a green run. Unset the
variable to have those 35 tests skip honestly.

## Generate a synthetic fixture

```bash
python - <<'PY'
import datetime
from tacho.fixtures.gen1_writer import make_sample_card_download
open("sample.ddd", "wb").write(
    make_sample_card_download(first_day=datetime.date(2026, 10, 5), number_of_days=5)
)
PY
```

Everything the writer produces is synthetic and generated from the regulation. **No
real driver data is stored in this repository, and none may be.** A real card carries a
person's name, date of birth and card number.
